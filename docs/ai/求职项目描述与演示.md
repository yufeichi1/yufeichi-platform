# 项目描述与演示材料

2026-11-05。以下描述面向已实现功能；最终测试、评测和发布状态以执行报告为准。开发有AI辅助，不写“独立精通所有实现”。在自己能够定位代码、修改与解释前，不把这些文字等同于已经掌握。

## Java / AI后端侧重点

为个人Yufeichi内容平台增量开发AI摘要、站内知识问答和受控只读助手，保持Java21、Spring Boot、MySQL及JWT权限体系。通过独立pgvector存储公开内容向量，结合MySQL可见性与内容hash复核来源；实现事务提交后的索引同步、幂等重建、有限重试与对账。为外部AI调用增加Redis配额、并发隔离、超时、取消与独立开关，并保留故障恢复和应用回退验证。

## AI应用侧重点

基于Spring AI接入外部Chat与Embedding服务，实现文章摘要预览与人工采用、带原文链接的RAG问答，将文章/项目查询封装为4个只读工具，并使用显式循环限制模型轮次与工具次数。建立30道固定评测题，对Top-K=3/5进行真实调用比较，记录召回、必要事实、引用、无答案与边界结果，并保留初测失败和修复记录。

可补充真实数字：最终评测每组18/18预期来源命中、18/18必要事实与预期引用通过，6/6无答案、6/6边界通过；必须同时说明是10个公开合成短文本源、30题，不能包装成生产效果或“大规模知识库”。不写提升百分比、QPS、节约工时、实习经历或商业用户数。

## 三场景演示顺序

1. 编辑页：输入明确标注的验收正文，生成真实摘要，先预览，证明不会自动写库，再人工采用、手动保存。说明正文变化为何使旧候选失效。
2. 知识问答：公开内容建索引，提问拿到依据，打开原文核对；再展示固定评测里的未知/私密负例记录。解释为什么向量库不是权限依据。
3. 只读助手：自然语言要求搜索并读取详情，展示真实工具步骤和原文。解释模型只提出请求，后端校验并执行；与固定Workflow的区别。
4. 故障记录：展示PG/Redis真实暂停恢复、模型500/超时、停止连接、关闭AI及旧JAR/V12兼容证据。不要在生产演示故障注入。

本轮短录屏无讲解音轨，截图和视频只说明实际流程；若录制完整约5分钟的个人讲解，可按上述顺序重新录，不以延长静止画面充数。密码、API Key、JWT、供应商专属地址和生产数据不得进入录屏。
